# แนวคิดและทิศทางการวิจัย: โครงการจำลองสังคมไทย (Thai Social Simulation)
อ้างอิงจากระบบ MiroFish และแนวคิด DEEDY Methodology

เอกสารนี้รวบรวมไอเดียทั้งหมดที่เราได้คุยกัน เพื่อใช้เป็นแนวทางในการรีเสิร์ช ออกแบบโครงสร้าง และพัฒนาโปรเจกต์ต่อไปครับ

---

## 1. สิ่งที่พัฒนาระบบ Backend ไปแล้ว (Core Tech Localization)
เราได้ปรับจูน "เครื่องยนต์" ของ MiroFish ให้รองรับบริบทของสังคมไทยเรียบร้อยแล้ว:
- **Thai NLP Processor**: ผสาน `PyThaiNLP` เพื่อให้ระบบสกัดเอนทิตี (Entity Extraction) และทำ RAG กับภาษาไทยได้แม่นยำขึ้น
- **Thai Demographics Model**: เปลี่ยนโครงสร้างการสุ่มสร้างประชากร (Synthetic Agents) จากฐานข้อมูลจีนเป็นโครงสร้างของไทย (เช่น อายุ, อาชีพ, ภูมิภาค)
- **Thai Time Schedules**: ปรับตารางความพฤติกรรม (Activity Multipliers) ให้ตรงกับเวลาทำการและช่วงเวลาพีค (Peak Hours) ของโซเชียลมีเดียไทย
- **Homophily Network**: เพิ่มตรรกะให้ Agent มีแนวโน้มจะกดติดตาม (Follow) คนที่มีจุดยืน (Stance) เดียวกัน
- **Trace-Grounded Reporting**: สร้างเครื่องมือให้ Report Agent ดึงสถิติจริงจากการรัน (Diffusion Scale, Polarization) มาเขียนรายงานเพื่อลดอาการ LLM "หลอน" (Hallucination)

---

## 2. โครงสร้างด้าน LLM (Language Models)
ระบบรองรับการทำงานผ่าน API มาตรฐานแบบ **OpenAI-Compatible** ทำให้มีความยืดหยุ่นสูง:
- **Cloud APIs**: สามารถต่อ API ของ OpenAI (GPT-4o), DeepSeek, Qwen หรือใช้ Proxy อย่าง LiteLLM เพื่อต่อกับ Claude/Gemini ได้
- **Local Thai LLMs**: หากต้องการใช้โมเดลภาษาไทยเฉพาะทาง (เช่น Typhoon, OpenThaiGPT, SeaLLM) สามารถรันบน Server ตัวเองผ่าน **Ollama**, **vLLM** หรือ **LM Studio** แล้วตั้งค่า Endpoint `LLM_BASE_URL` ชี้มาที่ Local Server ได้เลย

---

## 3. การเตรียมข้อมูลสำหรับ RAG (Knowledge Feeding)
เพื่อให้ Simulation ไม่โต้เถียงกันลอยๆ ข้อมูล (Text Documents) ที่จะป้อนเข้าระบบควรมี 3 ส่วนประกอบหลัก:
1. **The Event (เหตุการณ์ตั้งต้น):** เนื้อหาข่าวหรือไทม์ไลน์ดราม่าที่ระบุ 5W1H ชัดเจน (ใคร ทำอะไร ที่ไหน เมื่อไหร่)
2. **Background Rules (บริบทเชิงข้อเท็จจริง):** ข้อมูลกฎหมาย สถิติ หรือกฎระเบียบที่เกี่ยวข้องกับเหตุการณ์นั้น เพื่อให้ Agent ใช้อ้างอิงแบบมีหลักการ
3. **Social Stances (มุมมองทางสังคม):** ตัวอย่างความเห็นจากหลายขั้ว (สนับสนุน/ต่อต้าน/เป็นกลาง) เพื่อให้ระบบเข้าใจจุดยืนที่หลากหลายในสังคม

---

## 4. ทิศทางการรีเสิร์ช: Data-Driven Personas (Digital Twins)
หากมีการเขียน Script เพื่อดึงข้อมูล (Scraping) จากโซเชียลมีเดียจริง สามารถนำมาต่อยอดระดับ High-end ได้ดังนี้:

### 4.1 การสร้าง "Archetype" (ตัวแทนกลุ่ม)
- นำ Text ที่ Scrape มาจัดกลุ่ม (Clustering) เพื่อหาสไตล์การพิมพ์ (Tone of voice), คำสบถ/คำแสลง, และทัศนคติ
- ให้ LLM สรุปออกมาเป็น "Archetype Profile" แบบนิรนาม เพื่อใช้สร้างกลุ่มประชากร (Synthetic Agents) ที่พิมพ์โต้ตอบได้สมจริงเหมือนชาวเน็ตไทย

### 4.2 การสร้าง "Digital Twins" สำหรับ KOLs
- นำประวัติการโพสต์ของแกนนำ/อินฟลูเอนเซอร์ โยนให้ LLM สกัดออกมาเป็น MBTI, จุดยืน (Stance) และอุดมการณ์
- สร้าง Agent ที่ไม่ได้แค่พิมพ์เหมือน แต่มีกระบวนการ "คิดและตัดสินใจ" เหมือนบุคคลนั้นจริงๆ เมื่อเจอสถานการณ์ใหม่

### 4.3 โครงสร้างสังคมจริง (Empirical Social Topology)
- Scrape ข้อมูลความสัมพันธ์ (ใคร Follow/Retweet ใคร) มาสร้างเป็น Network Graph
- ป้อนกราฟนี้เข้าระบบ (แทนที่ระบบสุ่ม) เพื่อให้ข้อมูลในเกมแพร่กระจายตามท่อน้ำเลี้ยงหรือ Echo Chamber ที่มีอยู่จริง

> [!CAUTION]
> **ข้อควรระวังด้านจริยธรรม (Research Ethics & PDPA):**
> การใช้ข้อมูลจากการ Scrape ควรหลีกเลี่ยงการใช้ข้อมูลส่วนบุคคลแบบ 1:1 แบบไม่ได้รับความยินยอม วิธีที่ดีที่สุดคือการให้ LLM **"สรุปแบบนิรนาม (Anonymize)"** แล้วสร้าง Agent ขึ้นมาจากสถิติหรือค่าเฉลี่ยของกลุ่มนั้นๆ แทนครับ

## 5. งานวิจัยและการออกแบบที่ต้องทำต่อ (Next Steps for You)
- 📊 **Data Gathering:** หาแหล่งข้อมูล/ข่าว/แฮชแท็ก เพื่อนำมาทดสอบระบบ (Proof of Concept)
- 👥 **Demographic Research:** หาตัวเลขสถิติจริงจาก NSO (สำนักงานสถิติแห่งชาติ) เพื่อมากำหนดน้ำหนัก (Weights) ให้การสุ่มประชากรแม่นยำขึ้น
- 🖥️ **UI/UX Design:** ออกแบบหน้า Dashboard ว่านักวิจัย/ผู้ใช้งาน ต้องการเห็นกราฟสถิติรูปแบบไหน (เช่น ขั้วความขัดแย้ง, การกระจายข่าวสาร)
- 📝 **Prompt Tuning:** ปรับแต่ง System Prompt (ในฝั่งการรัน Agent) ให้มีการแสดงออกและบริบทความเป็นไทยที่ลึกซึ้งยิ่งขึ้น (เช่น การใช้ความเกรงใจ, ระบบอาวุโส)
